# Telemetry for YMM4

[![License](https://img.shields.io/badge/license-MIT-blue.svg)](#)
[![.NET](https://img.shields.io/badge/.NET-10.0-purple.svg)](#)

---

YMM4 のプラグインで発生した例外を開発者へ報告する、送信側のライブラリです。
受信は既設の GlitchTip が担い、本ライブラリは報告の組み立てと送信だけを扱います。
DLL ではなくソースとして各プラグインに取り込むため、プラグイン同士が互いの版に影響しません。
同意は求めず、報告は常に送信します。

## 概要

本ライブラリは、プラグインが捕捉した例外を Sentry の envelope 形式に組み立て、GlitchTip へ送信します。例外の捕捉は行わず、`TelemetryReporter.Report` を呼んだときにだけ動きます。

配布の単位は DLL ではなくソースです。プラグインのプロジェクトが `Telemetry.props` を読み込むと、`Telemetry` フォルダーのソースがプラグインのアセンブリに取り込まれます。DLL は増えず、ILRepack の対象にも加わりません。

同意を求める設定画面は持ちません。ソースを取り込む形では、設定の型も画面も取り込んだプラグインの数だけ増えるためです。報告は常に送信し、送信の事実は各プラグインの README に記載します。

## 動作要件

| 項目 | 要件 |
|---|---|
| 対象フレームワーク | .NET 10.0 |
| 対象プラットフォーム | Windows 10 バージョン 2004（ビルド 19041）以降 / Windows 11（64bit） |
| 参照するアセンブリ | YukkuriMovieMaker.Plugin.dll |
| 実行環境 | YMM4 上で動作するプラグイン |

参照する YukkuriMovieMaker.Plugin.dll は YMM4 本体に同梱されています。ビルドでは `YMM4DirPath` を通じて参照します。

## 導入方法

サブモジュールとして追加します。

```
git submodule add https://github.com/routersys/YMM4-Telemetry.git YMM4-Telemetry
```

プラグインの csproj へ 1 行足します。パスはサブモジュールを置いた位置に合わせます。

```xml
<Import Project="..\YMM4-Telemetry\Telemetry.props" />
```

## 使い方

例外を捕捉した箇所で `Report` に渡します。

```csharp
using Telemetry;

try
{
    Render();
}
catch (Exception exception)
{
    TelemetryReporter.Report(exception);
    throw;
}
```

設定は不要です。プラグインの名前とバージョンは取り込み先のアセンブリから決まります。

前回までに送れなかった報告を再送する場合は、初期化処理から `Start` を 1 度呼びます。すぐに戻るため、起動は遅くなりません。

```csharp
TelemetryReporter.Start();
```

利用するメソッドはこの 2 つです。ほかの型は `internal` であり、取り込み先のアセンブリの外からは見えません。

## 主な機能

### 1. ソースの取り込みによる配布

YMM4 の `PluginAssemblyLoader` は、`user\plugin` の下にあるすべての DLL を `Assembly.LoadFrom` で既定の `AssemblyLoadContext` へ読み込みます。同じ ID のアセンブリは最初に読まれた 1 つだけが採用されるため、共有の DLL を配ると、どの版が使われるかがディレクトリの列挙順で決まります。新しい版に合わせてビルドしたプラグインが、古い実装を読み込んでしまう事故が起こり得ます。

加えて `PluginLoader.GetDerivedTypesOf` は、すべてのアセンブリに対して `GetTypes` を呼び、例外を捕まえていません。型の読み込みに失敗する DLL が 1 つあると、プラグインの読み込み全体が止まります。

ソースを取り込めば、各プラグインが自分のアセンブリの中で完結します。ほかのプラグインが取り込んだ版とは無関係に動きます。

### 2. プラグイン間での状態の共有

ソースを取り込む以上、`static` な状態はプラグインごとに独立します。プロセス全体で 1 つにすべき状態は `AppDomain` のデータ領域を通じて共有し、複数の値をまとめて更新する箇所は、名前にプロセス ID を含めた Mutex で直列化します。

| 状態 | 共有の方法 |
|---|---|
| 送信数と重複の計数 | `AppDomain` のデータ領域。更新は Mutex で直列化 |
| 送信を再開できる時刻 | 同上 |
| 送信待ちの報告 | YMM4 のユーザーフォルダーの下のファイル |

セッション識別子は、プロセス ID とプロセスの開始時刻から決定的に導きます。乱数で作るとプラグインごとに別の値になり、同じ起動で起きた障害を突き合わせられません。

### 3. 送信数の上限と重複の抑制

報告の内容から指紋を計算し、同じ指紋の報告が上限に達したあとは送信しません。1 回の起動あたりの総数にも上限を設けます。上限はプロセス全体で共有するため、取り込んだプラグインの数が増えても総数は変わりません。

指紋は、例外の型と、自分のアセンブリに属するフレームのモジュール名と関数名から計算します。自分のアセンブリのフレームが 1 つも無い場合にだけ、すべてのフレームを対象とします。

受信側が 429 を返した場合には、`Retry-After` が示す時刻まで送信を止めます。この時刻もプロセス全体で共有します。

### 4. 送信できなかった報告の退避と再送

`Report` は、上限の判定と退避までを同期で行い、送信だけを非同期で行います。送信を始める前にファイルへ書き出すため、呼び出した直後にプロセスが終了しても報告は残ります。

退避先は、YMM4 のユーザーフォルダーの下の `telemetry` フォルダーです。1 件につき 1 ファイルを書き出し、件数と合計サイズの上限を超えた分は古いものから削除します。

`Start` を呼ぶと、前回までに送れなかった報告を古い順に再送します。送信に成功した報告と、受信側が受け取らないと判断した報告は削除します。通信に失敗した場合には、その場で中断してファイルを残します。

### 5. 個人に結びつく文字列の置き換え

例外のメッセージと、スタックトレースのファイル名に含まれる次の文字列を置き換えます。

| 対象 | 置き換え後 |
|---|---|
| ユーザープロファイルのパス | `[userprofile]` |
| AppData のパス | `[appdata]` / `[localappdata]` |
| ユーザー名 | `[user]` |
| 計算機名 | `[machine]` |
| ドメイン名 | `[domain]` |
| メールアドレス | `[mail]` |
| IPv4 アドレス | `[address]` |

ビルドしたときのパスは `PathMap` によって相対パスへ正規化します。これはビルドした人のフォルダー構成であり、利用者の情報ではありませんが、公開しているサーバーへ送る必要もありません。

置き換えが取りこぼす可能性があるため、受信側にも同じ検査を置いています。受信側は GlitchTip へ渡す前に内容を確かめ、違反を見つけた報告を上流へ渡しません。

### 6. 未処理例外への不介入

YMM4 は起動時に `DispatcherUnhandledException`、`UnobservedTaskException`、`AppDomain.UnhandledException` を自分で登録し、例外のウィンドウを出したうえで `Application.Current.Shutdown` を呼びます。

本ライブラリがこれらのイベントに登録すると、取り込んだプラグインの数だけ同じ例外を報告してしまい、YMM4 本体の例外処理にも干渉します。そのため登録は行わず、報告は呼び出し側が明示的に行います。

同じ理由から、送信を担うタスクは例外を外へ出しません。例外を漏らすと、`UnobservedTaskException` を通じて YMM4 が終了します。

## 送信する情報

| 種類 | 内容 |
|---|---|
| 例外 | 型の完全名、メッセージ、スタックトレース |
| フレーム | モジュール名、関数名、ファイル名、行番号、自分のアセンブリに属するかどうか |
| プラグイン | アセンブリ名、バージョン |
| 実行環境 | OS の名前とバージョン、.NET のバージョン、CPU のアーキテクチャ、論理プロセッサ数 |
| 識別子 | 起動ごとに決まるセッション識別子、報告ごとの識別子 |

メッセージとファイル名は、[個人に結びつく文字列の置き換え](#5-個人に結びつく文字列の置き換え)を適用したうえで送信します。

利用者の名前、プロジェクトの名前、素材の名前、ファイルの中身は送りません。継続して個人を追跡する識別子も持ちません。セッション識別子は、プロセス ID とプロセスの開始時刻から導く一時的な値であり、YMM4 を起動し直すと別の値になります。

送信元の IP アドレスは、GlitchTip へ渡す手前で取り除いています。

## 動作の上限値

| 項目 | 値 |
|---|---|
| 1 回の起動で送信する報告の数 | 20 件 |
| 同じ指紋で送信する報告の数 | 3 件 |
| 連鎖をたどる例外の数 | 5 個 |
| 1 つの例外から取るフレームの数 | 100 件 |
| 指紋の計算に使うフレームの数 | 20 件 |
| 退避する報告の数 | 50 件 |
| 退避の合計サイズ | 2 MiB |
| `Start` の 1 回で再送する報告の数 | 10 件 |
| 送信 1 回あたりの制限時間 | 15 秒 |

---

## 制限事項

- 例外は自動では捕捉しません。`Report` を呼んだときにだけ報告します。
- 第三者による偽装は防げません。Sentry のプロトコルは公開鍵をクライアントへ埋め込む前提であり、配布物から鍵を取り出せます。偽装の検出は受信側の役目です。
- 退避は YMM4 本体のユーザーフォルダーへ書き込みます。YMM4 の外で単体で動かす用途は想定していません。
- 上限に達したあとの報告と、退避から溢れた報告は捨てます。再送の対象になりません。
- 送信の成否は呼び出し側へ返しません。`Report` と `Start` は戻り値を持たず、通信の失敗と受信側の拒否も区別できません。

---

## 注意事項

- `Report` を呼んだ直後にプロセスが終了しても、退避した報告は次回の `Start` で再送されます。
- `Start` はプロセスの中で最初の 1 回だけ再送します。取り込んだプラグインの数によらず 1 回です。
- 送信に失敗しても例外は出ません。
- 置き換えは取りこぼす場合があるため、受信側でも同じ検査を行っています。

## 動作の確認

単体試験は次のコマンドで実行します。

```
dotnet test Telemetry.Tests/Telemetry.Tests.csproj
```

`Telemetry.Harness` は、単体試験では確かめられない部分を実際の構成で確認します。

| 引数 | 確認する内容 |
|---|---|
| `copies` | 2 つのアセンブリに取り込んだときの状態の共有と、報告の帰属 |
| `envelope` | 送信する内容の表示 |
| `send` | 実際の送信 |
| `ratelimit` | レート制限の挙動 |

```
dotnet run --project Telemetry.Harness -- copies
```

変異試験は `tools/mutations.json` に定義した変異を 1 つずつ実装に入れ、試験が落ちるかどうかを測ります。落ちない変異は、その振る舞いを守る試験が無いという意味になります。

```
pwsh -File tools/Invoke-MutationTest.ps1
```

Stryker.NET は使いません。この構成では変異体を評価できず、手で入れれば試験が落ちる変異を生存と報告したためです。
